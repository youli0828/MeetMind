# 小型业务评测（2026-11-06）

本评测复用仓库现有转写和纪要，无需网络、`.env`、LLM、音频或模型下载。
从仓库根目录运行（已安装 `.[dev]`）：

```powershell
& .\.venv\Scripts\python.exe docs/e2e/business-eval/evaluate.py
# 保存另一份结果：加 --output outputs/business-eval.json
```

默认更新本目录的 [results.json](results.json)，含逐问题结果、计数、版本及输入 SHA-256。
检索实际调用生产 `HybridRetriever`（默认 1200 字符分块、Chroma + BM25 + RRF），
使用 `OfflineModel` 的 64 维确定性哈希向量；SQLite 放在临时目录，Chroma 使用内存索引，结束后清理。
**这些数字属于离线基线，不代表线上 embedding 模型质量。**

## 数据与人工标注

[gold.json](gold.json) 显式保存两场会议的输入路径、查询、相关会议/分段 ID 和行动项：

- `sample-release`：包内原创虚构样例，3 个分段；2 条明确任务（安装说明、错误案例）。
  预测来自既有手写 demo 纪要，作为评分程序对照，不能当作模型抽取成绩。
- `alimeeting-base`：既有 `alimeeting-20261105-base-rerun/transcript.json`，107 个 ASR 分段；
  预测固定为同目录已保存的 `minutes.json`，来自历史真实 `glm-4-flash` 调用，未重新生成或润色。
  人工归纳 3 条后续建议：按年龄差别设计（78–85）、参与直播/电商活动（87–92）、
  前期扩大市场份额再调高价钱收益（93–98）。负责人和日期均无明确依据，标为 null。

标注时阅读现有文本，选择能定位到原段的 8 个问题（每场 4 个），列出回答所需的关键分段，
不要求列出所有语义重复段。行动项按“明确提出后续工作或建议”归纳任务，不把一般议题当任务，
不推测负责人和截止时间。使用建议而非已分派任务的宽口径；价格策略原文有 ASR 错误，
“前期低价”的概括存在解释空间。标注者可看到既有预测，未做盲标或第二人复核，也未按结果调标签。
Gold 是对当前 ASR 文本的人工理解，不是对原音频的独立事实核验。

## 计分规则

检索 Recall@k：将前 k 个块覆盖的 `(meeting_id, segment_id)` 去重，与 gold 关键段集合求交，
除以 gold 段数，再对 8 个问题取宏平均。没有相关度阈值；k 大于块总数时使用所有返回块。
保留生产分块参数，不为得到更好数字改小分块。

行动项给出两种 **set F1**，分别对每场会议评分，不把 demo 与真实预测混成一个模型成绩：

1. **字段 token 集合 F1**：NFKC、小写，中文按单字、英文/数字按词（复用检索 tokenizer），
   忽略标点和空白，不做繁简转换、同义词替换或语义匹配。
   每条行动项的 task/owner/due 转为 `(字段名, token)`，在整场会议内取并集，按精确相等匹配。
   P=交集数/预测数，R=交集数/gold数，F1=2×交集数/(预测数+gold数)。
   这会忽略重复、词序和任务边界，可能掩盖任务拆分、合并或责任归属错误；不是逐任务语义准确率。
2. **严格行动项集合 F1**：将轻度归一化后的 `(task, owner, due)` 整个元组作集合元素，完全相等才匹配。
   null 和空文本都视为空；不评分来源 ID（仅校验存在）。不设置模糊匹配阈值。

两集合皆空时 P/R/F1=1；仅一边为空时 F1=0。原始计数写入 JSON 供复核。

## 实测结果与边界

| 项目 | 结果 |
|---|---|
| 规模 | 2 场会议、2 个检索块、8 个问题；其中仅 1 场是真实会议 |
| 离线混合检索 Recall@1 / @2 / @3 | 1.000 / 1.000 / 1.000 |
| 已保存真实 LLM 纪要：字段 token 集合 P / R / F1 | 0.6667 / 0.6222 / **0.6437**（交集 28，预测 42，gold 45） |
| 已保存真实 LLM 纪要：严格行动项集合 F1 | **0.0000**（预测 3 条、gold 3 条，完全匹配 0 条） |
| 手写 demo 对照：token 集合 / 严格行动项集合 F1 | 1.0000 / 1.0000；不计为模型成绩 |

默认分块将每场会议都合为单块，因此 Recall@1 只检验两个明显不同主题间的排序，
@2/@3 覆盖全部候选，几乎必然满分；不能外推到多会议或长会议段级检索。
真实预测只有单场、3 条行动项，没有统计代表性；token 重叠不说明事实正确，严格 F1 又会惩罚合理改写。
线上 embedding Recall@k、大样本行动项语义 F1、说话人分离仍为 TODO。
本次没有实时 summarizer 调用；复测固定历史预测即可，不需要 live 开关，也不会隐式调用外部服务。
